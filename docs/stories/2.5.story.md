# Story 2.5: Code Quality and Type Safety Improvements

**Status:** Draft  
**Epic:** Epic 2 - Multi-instance Routing and Coordination  
**Story Points:** 8  
**Priority:** Medium  

## Story

As a **developer maintaining the popup-mcp codebase**, I want **comprehensive typing and data formatting improvements** so that **the code is more maintainable, less error-prone, and follows consistent patterns**.

## Acceptance Criteria

### AC1: Fix Loose Equality Comparisons
- **GIVEN** the codebase uses loose equality (`==`) in some places
- **WHEN** comparing values that should have consistent types
- **THEN** all comparisons should use strict equality (`===`) with proper type handling

### AC2: Standardize ID Property Usage
- **GIVEN** the code uses both `requestId` and `id` properties inconsistently
- **WHEN** handling request/response matching
- **THEN** there should be a single, consistent ID property pattern

### AC3: Replace `any` Types with Proper Interfaces
- **GIVEN** the codebase uses `any` types in many places
- **WHEN** these could be properly typed
- **THEN** all `any` types should be replaced with specific interfaces or union types

### AC4: Complete Empty Function Implementations
- **GIVEN** there are empty or incomplete function implementations
- **WHEN** these functions are called
- **THEN** all functions should have complete implementations

### AC5: Improve Type Consistency in Data Handling
- **GIVEN** data is converted between string/number types inconsistently
- **WHEN** handling IDs and other data
- **THEN** data types should be consistent throughout the request/response flow

## Tasks

### Task 1: Fix Loose Equality Comparison in WebSocket Response Matching
- [ ] **Location:** `src/backend/mcpServer.ts:229`
- [ ] **Issue:** `if (response.requestId == expectedId)` uses loose equality
- [ ] **Problem:** One ID is string, other is number - indicates type inconsistency
- [ ] **Fix:** Ensure both IDs are same type, then use `===`
- [ ] **Root Cause:** The comment says "Extract request ID from popup request (could be .id or .requestId)" - this dual property pattern is the real issue

### Task 2: Eliminate Dual ID Property Pattern
- [ ] **Location:** `src/backend/mcpServer.ts:226`

- [ ] **Fix:** Standardize on single ID property (`requestId`) across all interfaces
- [ ] **Files to Update:**
